# 识字卡片 · 儿童猜字游戏

一个**单文件、离线可用**的儿童识字卡片游戏（适合 4 岁左右）：先看字猜意思，翻到背面看图画，不会读就点发音。

打开方式：双击 `index.html`（Chrome / Edge / Safari 均可）。
在手机上「添加到主屏幕」后会以独立应用的方式打开（已接入 `manifest.json`、图标与 Service Worker）。

## 玩法

| 步骤 | 操作 | 说明 |
|---|---|---|
| ① 猜 | 看卡片正面 | 一个占满卡片的大字，底部是 2~3 个组词，先让小朋友认这是什么字 |
| ② 听 | 点「🔊 读一遍」 | **字 → 组词 → 背面讲解**，一次读完（正反面都是这一套，不用分辨现在在哪一面） |
| ③ 翻 | **点卡片上任何位置** / 点「🔄 翻面看图画」 | 卡片 3D 翻转；翻面时**自动按「字 → 组词 → 讲解」读一遍** |
| ④ 换 | **手机：左右滑动**；电脑：点 ◀ ▶ 或按 ← → | **安静翻页**：只换卡片，不发音（想听再点按钮） |
| ⑤ 找字 | 点左上角 **☰ 页码** 打开「全部汉字」抽屉 | 一眼看到当前牌组的全部汉字（默认收起），**点任意一个字直接跳过去** |
| ⑥ 声音 | 点右上角 🔔 / 🔕 | **一个开关管住所有声音**：提示音（翻面「叮」、揭晓铃声、翻页「嗒」）**以及语音朗读**。静音时会立刻打断正在读的内容，选择会记住 |
| ⑦ 护眼 | 点右上角 🌙 / ☀️ | 切换**白天 / 夜间底色**（选择会记住；首次打开会按当前时间自动判断） |
| ⑧ 分类 | 在字表抽屉里点分类胶囊，或点分组标题「只看这组 ›」 | 全部 / 基础 / 动物 / 植物 / 海洋 / 物品 |
| ⑨ 乱序 | 点「🎲 打乱」 | 在当前分类内随机打乱顺序 |

键盘快捷键：`空格` 翻面 · `←` `→` 上一个/下一个 · `I` 字表 · `Esc` 收起字表 · `R` 再听一遍 · `S` 打乱。

> 这行快捷键提示**只在电脑上显示**：触摸设备（`pointer: coarse`）或窗口宽度 ≤ 560px 时会自动隐藏，手机上不会占地方。

> **字表抽屉**：默认收起。打开后是当前牌组所有汉字的方格列表，当前这张字用橙色高亮并自动滚到可见位置；
> 点某个字 → 抽屉收起 → 卡片直接跳到那个字（安静翻页，不发音），此后 ◀ ▶ 就在这份完整字表里翻阅。

> 设计说明：4 岁孩子还不认拼音，所以卡片上**不出现拼音**，只保留汉字和组词。

## 怎么加新字

打开 `index.html`，找到对应分类的数组（`BASE` / `ANIMAL` / `PLANT` / `SEA` / `THING`），加一条即可（插画用内联 SVG，不需要任何图片文件）：

```js
{ char:'伞', words:['雨伞','打伞','伞花'],
  tip:'伞就是<b>下雨天的雨伞</b>，撑开像一朵蘑菇',
  pic: BG + `
    <path d="M100 30 C138 30 170 60 178 90 H22 C30 60 62 30 100 30 Z" .../>
    ...任意 SVG...` },
```

- `pic` 会自动包进 `<svg class="pic" viewBox="0 0 200 200">`，画布是 200×200
- 统一配色直接用 `P.green`、`P.orange`、`P.blue` 等（脚本里已定义）
- 分类标签的个数、卡片总数、计数器都会自动跟着更新；要加新分类就在 `CATS` 里加一行



## 趣味设计（让 4 岁孩子愿意一直点下去）

都是"轻"的：不抢注意力、不拖慢操作、不影响护眼。

| 动效 | 做法 | 为什么 |
|---|---|---|
| **大字轻柔浮动** | 4.2 秒一轮，上下 9px + 1.2° 微转 | 让画面"活着"，孩子会更愿意盯着看 |
| **卡片跟手倾斜** | 鼠标/手指移动时，卡片最多倾斜 5°（`pointermove` 改 CSS 变量） | 像"真的拿起一张卡片"，反馈感很强 |
| **插图按性格动** | 每个字配一个运动类型：会飞的**浮**、水里的**摆**、会跑的**点头**、车**转**、日/灯**呼吸**（`MOTION` 表，一行一个字） | 鸟在浮、鱼在摆、车轮在转——动效本身也帮着理解字义 |
| **汉字逐个蹦出** | 打开字表时，32 个字按 18ms 递延依次蹦出（上限 360ms） | 期待感，比"啪一下全出来"有意思 |
| **主按钮呼吸** | 「翻面看图画」有极慢的柔光扩散 | 明确告诉孩子"点这里" |
| **揭晓时刻** | 翻到背面时：插图从下方浮起 + 解释文字跟进 + 3 颗星星 + 一声轻铃 + 轻微振动 | 把"翻面"变成一个奖励动作 |
| **轻音效（可静音）** | 纯代码合成的正弦音（`AudioContext`），**不需要任何音频文件**：翻页极轻"嗒"、翻面"叮~"、揭晓双音 | 听觉反馈让操作更有"物理感"；不想要就点 🔔 关掉 |
| **触感反馈** | `navigator.vibrate` 轻微振动（支持的机型才有） | 手指上的确认感 |

刻意**没有**做的：自动播放背景音乐、满屏彩带、随机弹窗、会飘来飘去的吉祥物——这些会抢走孩子对汉字的注意力。

## 护眼设计（给小朋友看，这部分是刻意做的）

| 做法 | 具体处理 | 为什么 |
|---|---|---|
| **低蓝光暖底** | 页面底色从亮白改成暖白 `#fbf4e6`，卡片 `#fdf7ea`；环境光晕用暖黄、淡蓝、淡绿，都很淡 | 蓝光比例越低，瞳孔越放松，长时间看更不容易累 |
| **夜间模式** | 右上角 🌙 一键切换：深暖褐底 `#181310` + 卡片 `#241d17`；**刻意不用纯黑**（纯黑配亮屏对比更累眼） | 晚上/关灯时用，整个屏幕的发光量降一个档 |
| **插画一起降亮** | 夜间给插画加 `brightness(.66) + sepia(.22)`，浅色底板单独再压到 `.78` | 32 张插画里有大片浅色，夜里就是主要刺眼来源 |
| **不用纯黑字** | 大字用 `#262626`，正文用 `#2b2b2b`（对比度仍有 13:1，远高于标准的 7:1） | 纯黑+亮底是"高对比眩光"，稍微收一点更舒服 |
| **删掉所有闪烁** | 原来「👆 点卡片…」有个 1.5 秒无限闪烁的动画，已改成静态；星星从 5 颗减到 3 颗、幅度和时间都调小 | 周期性的明暗频闪是最容易引起视疲劳和不适的 |
| **动画变缓** | 翻面 0.62s → 0.75s，进入卡片的缩放从 1.16 倍降到 1.06 倍并加快到 0.3s | "快出场、慢收尾"，既不拖沓也不跳眼 |
| **对比度全部达标** | 白天最低 **6.05:1**、夜间最低 **7.32:1**（WCAG 正文要求 4.5:1，7:1 是更高一级的 AAA） | 文字看得清，眼睛就不用费力去辨认，这是最容易被忽略的护眼点 |
| **用眼提醒** | 连续使用 25 分钟弹一次「让眼睛看看窗外吧 🌳」；切到后台自动暂停计时 | 4 岁孩子的连续近距离用眼时间不该太长 |
| **尊重系统设置** | `prefers-reduced-motion` 关闭翻面与星星动画；`prefers-contrast:more` 加深卡片描边 | 系统里已经开过"减少动态效果"的孩子不用再设一遍 |

### 关于"护眼"要诚实说明的两点

- **软件改不了两件事**：屏幕的频闪调光（PWM）和蓝光峰值，那是硬件决定的。这里能做的是**降低画面总亮度、减少蓝光占比、去掉闪烁元素**。
- **最有效的永远是行为**：亮度别开太高（和环境光接近最舒服）、距离一臂、每 20 分钟看远处。所以内置了 25 分钟提醒。

### 界面上的「一个入口」原则

分类筛选原来在卡片上方排成一排胶囊，字表又是另一个抽屉——**同一件事两个入口**，而且那排彩色胶囊对 4 岁孩子只是干扰。
现在合并成一个：**左上角按钮 = 唯一入口**，点开就是完整字表，分类筛选也在抽屉里。顺带把卡片区上方那 49px 还给了卡片（手机卡片高度 666px → 709px）。

### 为什么这么拆

拆之前是一个 1325 行的 `index.html`，其中 **JS 占 67%**，而 JS 里**「32 张 SVG 插画」一个人就占了 480 行（36%）**。
真正的维护痛点不是 CSS 也不是逻辑，而是**内容都堆在页面里**：改个组词要在 1300 行里翻，加个字要同时动数据和运动表。

拆完之后，**加字 / 改词 / 改解释 / 画新插画，只需要动 `data/cards.js` 一个文件**。

### 两个刻意的取舍

| 决定 | 原因 |
|---|---|
| **用普通 `<script>`，不用 ES module** | ES module 在 `file://` 下会被 CORS 拦住，就丧失了"双击 index.html 直接玩"的能力。代价是 `data/cards.js` 用一个全局变量 `window.HANZI_CARDS` 暴露数据（全局变量仅此一个） |
| **`data/cards.js` 里存完整 SVG** | 逻辑层因此完全不用管 SVG 外壳，职责更干净 |

### 还能打包回单文件

拆开是为了好维护，单文件是为了好传播。需要时执行：

```bash
python3 tools/build_single_file.py                  # 输出 build/hanzi-single.html
python3 tools/build_single_file.py /tmp/卡片.html    # 指定输出
```

它会自动把 `styles.css`、`data/cards.js`、`app.js` 内联进 `index.html`，并去掉 Service Worker 注册。
生成的单文件双击就能玩，**不含离线缓存**，其它功能都在。


## 手机交互适配

手机上很多"桌面式"交互是不合适的，这一节记录做了哪些调整。

| 原来的交互 | 问题 | 改成 |
|---|---|---|
| 点 ◀ ▶ 翻页 | 小按钮 + 底部远离拇指，是桌面习惯 | **整张卡片左右滑动**：跟手位移、松手回弹；滑过卡片宽度 18% 或 320ms 内轻扫即翻页。滑出时**顺着手指方向**滑走并淡出，然后从另一侧淡入。**只支持左右**——上下留给页面滚动，不切换卡片 |
| 纵向滑动 | 可能被误判成翻页 | `touch-action: pan-y`：**纵向永远留给页面滚动**，只有横向为主的滑动才算翻页。上下滑**不会**切换卡片，这是刻意的 |
| 滑动后松手 | 浏览器补发的 click 会误触发"翻面" | 捕获阶段用 `stopImmediatePropagation`（只用 `stopPropagation` 拦不住同元素上的其它监听器）拦掉补发的那一次 |
| 多指触摸 | 小孩手掌多点屏幕会误判滑动 | 只认第一根手指，`pointerId` 全程校验 |
| 提示"点卡片翻到背面" | 没说怎么换卡片 | 触摸设备上自动变成「**左右滑动换一张** · 点卡片看图画」，并随窗口宽窄/横竖屏自动切换说法 |
| 卡片跟随鼠标倾斜 | 触摸下朝手指反方向转，手感怪 | 只在 `pointer: fine`（鼠标/触控板）时启用 |
| 小按钮（音效/护眼 38px、抽屉关闭 38px） | 低于 44px 的触摸目标标准 | 手机上放大到 40px / 44px |
| 按钮横排在窄屏被裁 | 6 个按钮挤一行会溢出 | 手机上隐藏 ◀ ▶ 和 🔊（大字本身可点读），剩下的按钮收紧尺寸，**零横向溢出** |
| 关闭抽屉要精确点 ✕ | 拇指够不到、目标小 | **抽屉上沿往下拖 64px 即关闭**（用 `setPointerCapture` 保证手指滑出标题栏也能收到事件） |
| **点卡片没反应、触发点诡异** | 原来是「点大字=朗读、点其它=翻面」，但大字的**行盒比可见字形高出一截**（0.92 行高 × 179px ≈ 165px），贴着字上方/下方点会被判成「点字」→ 既不翻面也不像朗读；而字周围其余空白是**完全没有监听的死区** | 卡片收敛成**一个功能：点哪都翻面**；朗读交给专门的按钮（「🔊 读一遍」，一个按钮读完整一遍）|
| 手机圆角/刘海遮挡 | 横屏时内容贴边 | 左右也加上 `env(safe-area-inset-*)` |
| **卡片竖长、虚线上方偏空** | 原来是 362×709（长宽比 1:1.96），大字周围空一大片 | 手机上收紧到 **1:1.13**（390×844 实测 335×379），大字随卡片高度缩放；宽屏手机用 `max-width:min(86vw,620px)` 而不是断点，各尺寸比例一致 |
| **手机上没有任何用法说明** | 底部那行是键盘提示，触摸设备上被隐藏了，家长不知道该滑还是该点 | 新增一行触摸专用说明：**左右滑动换一张 · 点卡片空白处看图 · 点大字听发音**（电脑上仍显示键盘提示） |
| **卡片浮在中间、上下都是空白** | 卡片和说明分散在两处，中间一大片空；卡片内部还被 padding + 一行重复提示吃掉 107px | 卡片与用法说明**放进同一个 flex 组**（`.stage` 改纵向列）、整体居中；删掉卡片内重复的短提示（foot 79→51px）；卡片放大到 `92vw`。390×844 实测：卡片 359×388、说明贴在下方 22px |
| **卡片比父层高 28px，压住了说明** | 手机断点里那条 `aspect-ratio` **写错了选择器**（写成 `.card` 而不是 `.card-swipe`），于是两层各按不同比例算高度 | 选择器改对，并给 `.card` 加 `aspect-ratio:auto; max-width:none` 做防御——尺寸只由位移层决定 |
| 长按弹出"拷贝/搜索"菜单 | 小朋友误触 | `-webkit-touch-callout: none` + `user-select: none` |

在 **320×568 / 360×640 / 390×844 / 430×932** 四种尺寸下用 Chrome 设备仿真（CDP `Emulation.setDeviceMetricsOverride`）实测：**横向溢出一律为 0**，◀ ▶ 正确隐藏，纵向手势不触发翻页。


## PWA / 手机上使用

这是一个完整的 PWA：**加到手机主屏幕后和原生 App 一样全屏运行，并且完全离线可用**（飞机上、车里都能给小朋友玩）。

| 文件 / 标签 | 作用 |
|---|---|
| `manifest.json` | 应用名、`display:standalone`（全屏无地址栏）、竖屏、护眼主题色、192/512 图标、`screenshots` |
| `sw.js` | Service Worker：首次访问后缓存整个应用，**断网也能打开**（页面内含 32 张内联 SVG，缓存下来就是完整应用，无外部依赖） |
| `icon-192.png` / `icon-512.png` | Android / Chrome 主屏幕图标 |
| `apple-touch-icon.png` | iOS 主屏幕图标（180×180） |
| `.nojekyll` | 告诉 GitHub Pages 不要用 Jekyll 处理 |
| `<meta name="apple-mobile-web-app-*">` | iOS 全屏运行、主屏幕名称「识字卡片」、状态栏跟随护眼底色 |

### 手机上怎么装

- **iPhone / Safari**：打开网址 → 底部「分享」→ **添加到主屏幕**
- **Android / Chrome**：打开网址 → 右上角菜单 → **添加到主屏幕**（或等它自动弹出安装提示）

装好之后从主屏幕图标进入就是全屏的，没有地址栏和浏览器 UI。

### 部署到 GitHub Pages

所有资源**一律使用相对路径**（没有任何以 `/` 开头的绝对路径），所以放在**子路径**下也能正常工作。

1. 把 `kids-hanzi` 目录里的文件推到仓库（例如 `main` 分支的 `kids-hanzi/` 目录，或独立仓库的根目录）
2. 仓库 **Settings → Pages**，Source 选 `Deploy from a branch`，分支选 `main`、目录选 `/ (root)`
3. 等一两分钟，访问：

```
https://<用户名>.github.io/<仓库名>/              # 放在根目录时
https://<用户名>.github.io/<仓库名>/kids-hanzi/   # 放在子目录时
```

两种路径都验证过兼容：`manifest.json` 的 `start_url` / `scope` 用 `"./"`，`sw.js` 用相对地址注册，Service Worker 的预缓存清单也全是 `./xxx` 形式。

> 更新代码后如果手机上还看到旧的：静态资源是「缓存优先 + 后台更新」，**下次打开就是新版**。
> 想强制所有人立刻刷新，把 `sw.js` 里的 `CACHE = 'hanzi-cards-vN'` 版本号 +1 即可。

## 实现要点

- **发音**：Web Speech API（`speechSynthesis`），自动挑中文音色（PingFang / Tingting / Google 普通话），语速 0.8、音调 1.1，完全离线、不需要音频文件。
  - 若浏览器不支持，会提示改用 Chrome / Safari，其它功能不受影响。
- **何时发音**：只有「点读一遍」和「翻开背面」才发音，且都是**字 → 组词 → 讲解**完整一遍；**左右翻页保持安静**。
- **插画**：32 张手绘内联 SVG，无外部依赖、无网络请求，任意分辨率都清晰。
- **卡片翻转**：CSS `transform: rotateY()` + `backface-visibility`，纯 CSS 3D 动画。
- **响应式**：手机竖屏自动精简按钮文字、缩小卡片，并隐藏只对键盘有意义的快捷键提示，单屏放下不用滚动。
- **护眼**：白天/夜间两套暖色调主题（右上角切换，localStorage 记忆），插画随主题降亮，无闪烁动画，对比度全部达标。


## 一次自我代码审查发现并修掉的问题

用独立视角做了一轮对抗式审查（配合一个能真实跑 `app.js` 的 DOM 桩派发合成事件），发现并按优先级修掉：

| 级别 | 问题 | 修法 |
|---|---|---|
| 严重 | **切卡动画方向反了**：`dir`（翻页方向，左滑=+1）被复用成了退出方向，于是往左滑时卡片先被推到**右边**再消失——就是你感觉到的"先往右弹一下"。逐帧测出：`-125 → -57 → +13 → +81 → … → +363` | 拆成两个变量：`dir` 只管翻页，`exit = Math.sign(dx)` 只管退出方向 |
| 严重 | **淡出/滑入根本没动画**：位移和透明度写在**未注册的 CSS 变量**（`--dx`/`--dop`）里，而 Chrome 对未注册变量做的是**离散插值**——过渡会瞬间跳变（`-294/0.02` → `0/1.00` 一帧完成） | 新增一层 `.card-swipe` 位移层，直接动画真正的 `transform` 和 `opacity`；卡片本体（`preserve-3d`）只负责翻面/倾斜/缩放，两边互不干扰 |
| 严重 | **手机上滑动切换卡片完全失效**：滑动判定成功后调用了 `setPointerCapture()`，而触摸指针本身已有"隐式捕获"，浏览器随即补发 `lostpointercapture`，我那个"兜底"处理器把它当成手势结束，立刻把卡片复位——`--dx` 永远是 0。**这个问题用 CDP 派发真实触摸事件才复现出来**（鼠标拖拽一切正常，早先的自动化测试因此全部漏过） | 滑动路径**不再调用 `setPointerCapture`**（触摸隐式捕获已足够），鼠标拖出卡片的情况改用 `window` 上的 `pointerup` 兜底 |
| 严重 | **抽屉下拉关闭会把抽屉卡在半空**：`pointermove/up` 只挂在 70px 高的标题栏上，手指一滑出去就再也收不到事件，`finish()` 不执行，内联 `transform` 永久覆盖 `.drawer.open{transform:none}` | 标题栏 `setPointerCapture` + `touch-action:none` + `lostpointercapture` 兜底；收尾用 `removeProperty` |
| 严重 | **点「听一听」后 900ms 内换卡会读错卡片**：`setTimeout(sayWords, 900)` 在触发那一刻才取 `cur()`，于是念出新卡的组词，还掐断新卡自己的朗读链 | 回调里先抓快照，`cur() !== d` 就放弃 |
| 严重 | **一条坏数据就让整个应用白屏**：`elPic.firstChild.classList` 在 `pic` 为空时抛错；`order` 为空时 `cur()` 是 undefined。启动阶段抛错会让 IIFE 直接死掉（无主题、无监听器） | `render()` 加空值保护、改用 `firstElementChild`，启动时校验 DATA 并给出可读的降级提示 |
| 中 | **多指触摸会误翻卡**：`active/sx/sy` 是单份共享状态，没有绑定 `pointerId`，小孩多指点屏幕（很常见）就会误判滑动 | 只认第一根手指，`pointerId` 全程校验 |
| 中 | **滑动后 400ms 内的正常点击被吞**：防浏览器补发 click 用的时间窗太粗暴，孩子滑完立刻拍卡片不翻面 | 改成"只拦补发的那一次 click"，不再用时间窗 |
| 中 | **空格/回车在按钮上双触发**：焦点在「翻面」上按空格，浏览器派发 click 翻一次 + 全局快捷键又翻一次 | 焦点在 `button` 上时直接让给浏览器；抽屉打开时屏蔽全局快捷键 |
| 中 | **抽屉没有焦点陷阱**：纯键盘用户能 Tab 到背景按钮，但因 backdrop 覆盖又点不动，掉进死区 | 打开时给 body 加类让背景 `pointer-events:none`，焦点移到关闭按钮；关闭时把焦点还给 ☰ |
| 中 | **`)aria-hidden` 包着焦点元素**（违规且读屏会丢焦点） | 关闭前先把焦点还出去 |
| 中 | **选中的分组标题几乎不可读**：`.dglabel.on` 与 `.dglabel .go` 选择器权重相同，后者在文件更靠后而胜出，整行被套上低对比度颜色 | `.dglabel.on` 只加深本体（实测 13.4:1） |
| 中 | **按钮白字对比度约 2.6:1**（与文件里"全部 ≥4.5:1"的注释自相矛盾） | 新增一组加深版按钮底色 `--btn-*`（插画仍用明亮主色）；实测 4.77~5.95:1 全部达 AA |
| 中 | **夜间缺 `color-scheme`**：原生滚动条仍是亮色，与护眼目标冲突 | `:root{color-scheme:light}` / 夜间 `dark` |
| 中 | **Service Worker 的 `controllerchange` 会在首次安装时无谓刷新一次**，打断正在玩的孩子 | 只在"已有控制器被替换"时才 reload |
| 中 | **打包脚本的 `re.sub` 替换串未转义 `$`**（`$&`/`$1` 陷阱），一旦数据里出现这些字符就静默产出坏文件 | 改用替换函数 + 内联前检测 `</script>` 并报错退出 |
| 中 | **manifest 声明的截图尺寸与真实不符**（写 540x545，实际 540x544），会让 Chrome 的富安装校验失败 | 按 PNG 头实测值改正 |
| 中 | SW 导航刷新用 `fetch(req)` 拿的是 HTTP 缓存，GitHub Pages 的 `max-age=600` 会把版本错配窗口拉长到 10 分钟 | 改 `fetch(req, {cache:'no-store'})`，缓存版本 → v6 |
| 轻微 | 残留死代码：无对应元素的 `.counter` 样式、占位用的 `card.dataset.justSwiped` | 清掉 |

**故意没改的两项**（记录判断，避免以后重复纠结）：

- **SW 的"新 HTML + 旧 JS"错配窗口**：根因是导航每次都取新 HTML、静态资源走缓存优先。彻底解决要给资源加 `?v=` 版本参数（构建期注入），会让 `data/cards.js` 的引用方式复杂化。对"改完重新部署、隔天再看"的节奏影响很小，先不动；真要发版时把 `CACHE` 版本号 +1 即可。
- ~~`icon.png` 1.7MB 源图~~：**已删除**。它没有被 manifest/Service Worker 引用（那两个只用 `icon-192/512`）。
  如果以后要换图标，重新提供一张方图，按 `python3 -c "from PIL import Image; ..."` 生成 192 / 512 / 180 三个尺寸即可。
